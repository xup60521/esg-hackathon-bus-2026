# 6670 可信旅遊問答（檢索式原型）報告

研究與實作日期：2026-11-04（Asia/Taipei）。方向：A-007 十個應用之 #7「AI 客服或智慧旅遊資訊服務」，限定 6670 範圍。頁面：`/lab/assistant`。

## 摘要

- 做了一個**沒有接任何生成模型、不需要 API key** 的檢索式問答：答案全部來自三類有來源的資料——官網文字（人工整理成知識庫）、官網靜態時刻表（程式擷取並驗證）、2024–2025 歷史刷卡統計（由專案既有彙總產生）。沒有依據就拒答。
- 每個回答標示資料依據（官方文件／官網表定時刻・非即時／歷史刷卡／官網圖片・人工目視）、來源連結、擷取日期，並附「限制」說明。
- 明確拒答：即時位置、誤點、剩餘座位、是否客滿或被拒載、人潮預測、國定假日班次、未轉錄的起訖站票價、退改票、天氣停駛、景點營業與住宿、其他路線。
- 驗證：時刻表 4 張表每班站間時間單調；歷史彙總與 README 的 1,800,910 筆守恆；所有單一站名起訖組合（29×28×2 日型＝1,624 組）的班次查詢與獨立暴力實作逐筆一致；62 題自撰問答驗證集 62/62 通過（見「驗證」對自撰題庫的保留）。`bun test src` 全專案 198 通過、0 失敗。
- 研究上的重要發現：官網「票價」不是單一數字——路線頁寫單程 193 元，但官網票價表（圖片）依上車站、路線與付款方式（現金／IC 卡）分列，且高鐵臺中站→日月潭與臺中干城站→日月潭不同價；官網時刻表頁另有 115/11/1 機場線調整公告，機場線路線頁未同步。這些差異都在答案中揭露，而不是挑一個數字。

## 方法

規則順序（`src/features/lab/assistant/engine.ts`，先擋再答）：

1. **即時／座位／預測 → 拒答**。含「現在、目前」搭配座位、客滿、誤點等，或「還有位子嗎」「下一班幾分鐘到」。「ibon 票有沒有保留座位」這類購票規定不算即時。
2. **範圍外 → 拒答**：天氣停駛、退改票、住宿／門票／步行距離、其他路線。
3. **特殊日期**（國定假日、連假、春節、寒暑假）問班次 → 拒答；官網只定義「平日＝周一~周四、假日＝周五~周日」。
4. **票價**：先檢查起訖站組合，只有 4 組有轉錄（臺中干城⇄日月潭、高鐵臺中站⇄日月潭、台中⇄埔里 6670H、機場⇄日月潭）；其他組合拒答並指向官網票價表，**不用距離估算**。
5. **班表查詢**：從問句抽取起訖站（長站名優先，「日月潭線」不當站名）、時間（9 點、下午 3 點半、十二點）、星期、「前／後」、首末班；由時刻表資料回傳。要求起訖站都有時間且方向正確（避免把反方向或不停靠的班次列出），起站為終點的班次不算上車。未指定星期兩種表都列；未指定時間列首末班。「今天／下一班」用使用者裝置的台北時間，取不到就要求補充。
6. **歷史統計**：指定站點的平均每日上車刷卡尖峰時段與星期分布；沒有該站紀錄就拒答。
7. **知識庫關鍵字檢索**：每條有觸發詞與必要詞，命中詞長加總過門檻才回答；否則「沒有可靠的依據」。

介面沿用 `/lab` 的共用元件（LabShell 由 `lab.tsx` 提供、`KindBadge`、`Section`、`FreshnessBanner`、`LimitationList`、`Provenance`、淺／深色 token），只新增問答版面與回答卡。

## 實際結果

### 官網資料的研究發現

- **票價有三層差異**（官網路線頁原文 + 票價圖片目視）：路線頁寫「單程 193 元，來回 360 元」。B 線票價圖（標題「日月潭線B線(經埔里)」）現金欄：臺中干城站→日月潭全票 193、高鐵臺中站→日月潭 166；IC 卡欄分別為 169、146。因此旅遊部落格看到的 166 與 193 都不是錯，只是起訖站與付款方式不同。此判讀由人眼完成，未逐格核對，也只看了 B 線；該圖標題寫「經埔里」，與路線頁「B 為直達」不一致，顯示官網圖片可能有標示錯誤。系統因此只把它當「官網圖片・人工目視」並附警語，不外推到其他線或起訖站。
- **客滿規定**（路線頁原文）：行駛國道路段，如遇客滿或已有預約保留席位，則無法於中間站點再載客，建議到干城站、高鐵台中站排隊。這是官方對「中間站可能上不了車」的一般性說明，可用來回答「客滿時中間站能不能上車」；但系統不判斷某站某班是否上得了車，刷卡資料也不能證明拒載。
- **機場線異動**：時刻表頁寫 115 年 11 月 1 日起機場線改繞福興溫泉區（新增福興溫泉遊客中心、地理中心碑，取消埔里花卉中心）並調整時刻表；機場線路線頁沒有提到。機場（6670E）班次在時刻表上只出現在**平日**表（去程 09:00、14:30；回程 08:35、13:55），假日表沒有；查詢時會明示「假日表上沒有符合的班次」，而不是靜默省略。
- **班次無法對應子路線**：時刻表只有序號，沒有 A–F 標示；本專案刷卡資料有 A、B、D、E、F、H 而沒有 C。系統不把班次歸給子路線。
- 官網把「平日」定義成周一至周四，與一般認知（周一至周五）不同；周五使用假日表。回答與提示都顯示這個定義。

## 限制

1. 沒有生成模型：只能回答人工整理與資料查詢涵蓋的問法；措辭差異可能被判「沒有依據」，這是故意偏向漏答而非編造，但使用者體驗有限。多輪對話、指代（「那回程呢」）不支援。
2. 官網資料沒有更新日期、規定可能已變；官網各頁可能不同步。時刻表是擷取當下的快照，需要時重跑腳本；官網改版會使解析在站數、表數不符時失敗而不輸出。
3. 票價：官網票價表是圖片，只轉錄 4 組起訖站，且高鐵臺中站→日月潭為人工目視、未逐格核對、只看 B 線。其他起訖站、IC 卡價、各線差異都沒轉錄。
4. 班次序號不對應子路線 A–F；國定假日、連假、寒暑假無法回答；平日／假日採官網定義（周一~四／周五~日）。機場班次僅平日表有。
5. 歷史統計：只是成功刷卡人次；星期用日曆星期，不排除國定假日，與官網平日／假日分法不同；同站各子路線合併；方向以站序推定，方向未知的刷卡未納入；缺 6 天不代表停駛。不能推論客滿、拒載、候車或需求。
6. 站名比對：「埔里」固定算埔里站（轉運站）、「台中」固定算臺中干城站、「暨南大學」取該班有停靠的校內或校外站；答案內會註明。罕見別名可能認不出來。
7. 沒有即時資料：官網「公車動態」只確認連結存在。TDX 6670 的覆蓋與延遲未查驗。
8. 沒有使用者研究，沒有衡量使用者能不能更快找到資訊。
