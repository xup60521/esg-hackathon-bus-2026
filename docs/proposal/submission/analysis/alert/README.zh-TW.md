# W1 預警回測：研究草稿

【事實】最新版結果在 `v2/metrics.json` 與 `v2/dashboard_data.json`；根目錄舊版先前使用以未來可評估性篩出的前班資料，存在洩漏，**不可使用**。v2 改以所有重建到站計算同站前班，時間必須嚴格早於預測時刻。這份回測仍有下述重大限制，**尚不能證明可即時上線或作為每日提示量預算**。

## 方法與選樣

【事實】使用 2024-01 至 2025-03 訓練、2025-04 至 06 選模型及門檻、2025-07 至 12 留出。每車每日按上車時間、乘客旅次方向、站序遞進及 90 分鐘切 run；同站相鄰上車不超過 10 分鐘合併。站序增加為往日月潭方向，減少為反方向。只保留已有至少兩個不同上游觀察站、方向能由這兩站判斷，且下一個觀察到的下游到站屬指定 12 站、到站前載客大於零的事件。上游最後上車時間為離站代理，包含同秒上車，目標站第一筆上車前計載客；同秒下車先處理。特徵含代理時刻小時、星期、休息日、連續休息日、上游子路線與站、方向、目標站、上游載客與同站上一筆到站間隔。連休係相鄰至少一日同為 rest，非政府公告連假認定；calendar note 保留於內部事件，但未納入模型。預測時間及前班時間嚴格比較；方向需由已觀察兩站的站序判斷。

【事實】重建 73,030 個 run、平均 2.658 個觀察停靠；194,090 個停靠與既有到站檔 193,715 筆相差 375（0.19%），僅為總量比較，並非逐筆吻合率。可評估 48,756 筆，訓練／選擇／留出各 30,288／6,146／12,322；既有檔 12 站 load>0 為 71,335 筆，兩種重建口徑不同，48,756 / 71,335 = 68.3% 僅是規模對照，不能當逐筆覆蓋率。

【事實】站序下一站版本的探索計數：187,809 個具下一站序的觀察停靠中，後續下一個觀察停靠恰為該站序的有 5,712（3.04%）；其餘不能視為負例。此計數涵蓋全路線，並非只限 12 站，且尚未建立該版本的獨立預測表；站序可能有路線分支或缺站，因此此比例不是實際通過該站的可觀測率。

## 重要限制與使用

【事實】只有成功刷卡乘客；現金、漏刷、無人上車、被留下者均不可見。車牌沒有車型對照，因此 41／37 席是分開情境，並非實際車型；不應由異常推估載客指控超載。run 切分使用旅次最終下車站序，屬事後重建；雖方向特徵來自已發生的站序，run 邊界仍可能依賴未來資料。上游「最後」一筆刷卡必須等之後才知道是最後一筆，沒有獨立可即時觀察的發車訊號。目標事件選擇本身使用未來是否有人上車；目前沒有涵蓋所有候選站的即時事件產生器。因此上述結果屬條件式回顧性分析，不能當作無洩漏的實際部署評估。需要真實離站／定位資料、即時可取得的方向及班次狀態，並在所有預先指定的候選目標站上前瞻評測。

【事實】`dashboard_data.json` 約 300 KB；`summary` 為模型與操作點，`replays` 依四種情境及工作日／非連續休息日／連續休息日各擇一留出日，事件中 `p`、`t` 為 Unix 秒，分別是上游代理與下游到站時間，`stop`、`upstop` 為站名，`route`、`direction` 分別為子路線與站序方向（1 增、-1 減），`up_load` 為上游載客，`probability` 為選出模型機率，`alert` 使用 N=5 門檻，`load` 為下游到站前載客。事件僅含可評估樣本，不能當成全量當日提示重播。
