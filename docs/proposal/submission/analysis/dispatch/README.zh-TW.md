【推論】上述窗口可供業者優先核對班表和車型，不能據此判定應加班或調整無障礙車。上車人次不等於無座人次。JSON 每窗口含按日期叢聚的比例標準誤，反映同日到站相關性；不涵蓋重建系統誤差。

【限制】到站檔沒有車碼或班次識別，尚未由原始旅次完成班次重建，因此無法可信估算相鄰班次不均、每加班緩解量、車型指派、成本與碳平衡點。JSON 對未完成項目使用 null；不可把它們視作零。僅可見成功刷卡者，無法量測被留下的人；重建載客可能出錯，不可據此指控超載。車型和車牌對照未知。不同日的近似獨立假設也可能不成立。

## 重跑

使用環境 Python，將輸出指定到不存在上述兩個檔案的資料夾，程式以唯讀模式檢查資料庫，並由本專案讀取已重建到站與日曆：

```sh
python analyze.py /path/to/trips.db --out /path/to/new-output
```

dashboard_data.json 的 windows 為子路線、方向、小時、日類細分；denominator 為 load>0 到站數，near41／near37 為門檻到站數，boarded41／boarded37 為這些到站的上車人次，rate 為對應比例，se_day_cluster 為日期叢聚標準誤；top10 按 near41 排序。scenario_a、scenario_b、cost_carbon 為 null，表示未完成。
