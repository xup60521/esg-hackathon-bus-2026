# 6670 旅次 OD 人工規則分類

本研究統計電子票證旅次的起訖站、時段與票種。規則依序分組，沒有 ML 訓練、分群模型或特徵聚類。它不能辨識搭乘目的、個人身分、回程或轉乘鏈。

資料來源是本專案 `trips` 表。重產程式只讀取聚合結果，不輸出逐筆旅次。查詢在單一 read transaction 快照內進行，窗口為 `2024-01-01 <= board_date < 2026-01-01`；`board_date` 定義為 Asia/Taipei 上車日期。小時以 Unix 秒加8小時轉換；另查 `board_date` 與時間戳本地日期是否一致。資料源規格見 [schema.ts](../../../src/db/schema.ts)。

有上下車站的單程紀錄可計算 OD。`midstop.json` 僅有各站上下車邊際計數，不能重建配對 OD。來源 schema 不存卡號或駕駛識別碼；本輸出只包含聚合欄位。沒有卡號，不能追蹤個人回訪、回程或多運具轉乘。刷卡量也無法證明潛在需求、候車時間、拒載或滿載。

## 分析口徑

- 缺站以 `trim(coalesce(stop, '')) = ''` 查詢，涵蓋 NULL、空字串及一般空白。下車站缺失與下車時間缺失分別計數。保留原始非空站名，不自行合併異名站。
- 時長為 `alight_ts - board_ts`。只以 `180 <= 秒數 <= 21600` 的樣本計算平均。OD 與群都先合計整數秒數與有效樣本數，再除60並四捨五入一位小數；無有效樣本為 null。
- 短於3分鐘只是分析排除，可能是真實短途，不代表誤刷。`under3Min` 僅計正值不足180秒；零、負值、超過6小時、缺時間另列，與有效樣本互斥。這些排除不刪旅次總量、票種或每小時計數。
- 同站 OD 另設待查組，不論時長。它與短時排除可能重疊，不能把兩者混稱或直接相加。原因 unknown，未查票價或驗票機事件，不能推測誤刷、測試或解卡。
- `activeDatesCount` 僅有紀錄的不同日期數，不是營運日數，也不代表連續日期。
- `weekend` 僅週六日，未套用政府假日日曆。AM 為06:00至09:59，PM為16:00至19:59，其餘時段為 offPeak；這些時段是預先指定分析窗口，不表示已驗證實際尖峰。
- 票種依名稱優先序互斥分類：學生／暨南大學／聯合科大 → 敬老／愛心／博愛／陪伴／仁愛 → 通勤／中彰投苗／境市民字樣 → 一般／全票／指定電子錢包名稱／優待票 → other。保留既有名稱對應，但不把它當成人口或法定票種資格驗證。完整名稱對應與筆數見 audit 的 `rawTicketGroups`，overview 和每個 OD 都用同一個函式。

## 規則與輸出

依序為同站、暨南大學名稱站／崎下端點或學生票占比至少25%、臺中端至日月潭／九族端點、臺中端至埔里端點、有效平均時長不逾50分鐘且至少1000筆、其餘 OD。門檻是人工設定，沒有以外部標註驗證。週末、AM與PM沒有參與分類。不能從 `regional_commute` 等 legacy enum 字面推論通勤、觀光、就學、返鄉、採買或高齡人口。

[summary](../../../public/data/lab/behavior/od-behavior-summary.json) 的 `allOdPairs` 包含完整 OD；前30僅在 `topOdPairs`。每群只列前5代表 OD，時段檔僅前10 OD，均非完整列表。[audit](audit-summary.json) 保留本次 metadata 聚合、原票種對應及逐項對帳；對帳證明當次快照的總數一致，不能證明來源漏失率為零。

執行程式見 [build-behavior-data.ts](../../../scripts/lab/behavior/build-behavior-data.ts)，回歸測試見 [behavior.test.ts](../../../src/features/lab/behavior/behavior.test.ts)，獨立重算對帳見 [verify.ts](../../../scripts/lab/behavior/verify.ts)。整合 breaking changes 與命令見 [整合契約](integration.zh-TW.md)。本次未建立或變更 UI、路由與視覺。
