# 中站上車低窪分析

目標：在現有網頁新增分析入口，觀察頭尾站高峰是否伴隨中站上車量下降。這是待驗證的統計線索，不能標示為已證實拒載或客滿。

資料：執行 `bun scripts/analysis/export-midstop.ts` 從既有 Turso DB 唯讀匯出 `public/data/midstop.json`。每列為 `[date, subroute, direction, stop, hour, boardings, alightings]`。上車和下車依各自實際發生時間分桶，Asia/Taipei。SQL 見 midstop-query.sql。匯出以月份切分，利用 board_date 索引；成功月份快取於 git 忽略的 data/midstop-months，失敗重跑可續傳。跨月下車事件會合併，並核對上下車總數後才發布 JSON。沒有個人識別資訊或車牌。

方向依 public/geo/stops.json 的 order 對 OD 起訖站推定，outbound 為台中往日月潭，inbound 反向。同站/未知 OD 標 unknown，方向分析須排除並顯示數量。不使用原始 board_seq 大小推定方向，因其可能為收費站序。地理順序不是正式班次停靠表，沒有班次 ID，不能宣稱同班車的因果關係。

建議功能：
- 新增可導航的分析頁，保留首頁既有 3D 視覺化，首頁加入入口。
- 日期範圍、支線、方向、頭尾站及中站選擇。頭尾站可自訂，因 H 到埔里且各支線不同。站點集合互斥；不要默默把所有「埔里」都當中站或都當端點。
- 觀察頭尾站上車、頭尾站下車、中站上車，獨立指標不要加總成「壓力」。目的地的下車高峰與起點上車高峰發生時間不同。
- 提供時間差 0/1/2 小時，明確說明是將參考站時間 t 與中站時間 t+lag 對齊，不跨不存在日期補零。日期邊界要正確。
- 同星期、同月份、同支線、方向、時段的平均中站上車量可作基準；觀察日從基準排除，基準不足顯示無資料。僅對確定有該支線紀錄的日期建立零值時段，缺失整日不補零；零值不代表真的有班次。
- 先展示原始量，再展示中站相對基準偏差；不要只用占比下降當搭不上車，因為分母增大就會讓占比降低。
- 若做相關係數、分位數或高峰低窪標記，清楚交代公式/門檻/配對數，樣本不足或常數序列回傳 null。
- 可顯示可下載篩選後 CSV，保留數據可檢核性。

解讀限制：刷卡紀錄只看到已搭上的人，無候車/未上車/容量/預約/實際班次資料。中站上車量降低也可能是需求變化、天候、停駛、改道或其他因素。沒有低窪也不能排除拒載。資料是 2024–2025 年歷史，非即時。
