## 3 新引入或殘留的錯誤與矛盾

**N1［事實］A0 的內部使用狀態前後不一（殘留，影響最大）。** PLAN §3 第 40 行寫「權限未確認時不提交也不發布，內部使用亦待確認」；H 第 3 行寫「在未確認前僅作團隊內部草稿」；H 第 69 行另要求內部草稿保留原數字。H 允許的用途，正是 PLAN 認定尚未確認的用途。PLAN §1 第 24 行仍把 A0 列為「黑客松內交付」。

**N2［事實］H 的「起點或端點站」分類對高鐵臺中站有誤。** H 第 32、34 行把臺中、台中航空站、高鐵臺中站、日月潭列為起點或端點。依 `public/geo/stops.json` 的去程序列，台中航空站為 seq 1、臺中為 seq 2、高鐵臺中站為 seq 6（介於臺中與牛耳石雕公園之間），高鐵在中段。PLAN §0 亦描述路線為「臺中 ⇄ 高鐵臺中站 ⇄ 埔里 ⇄ 日月潭」。若部分班次以高鐵為起訖，H 應註明，目前未見來源。台中航空站與日月潭的分類可由 stops.json 支持。

**N3［事實／推論］小格規則範圍不一致且不完整。** (a) PLAN §8 第 171 行只說「對外版抑制」，H 第 69 行則說「對外或提交評審的版本」。(b) H 只遮分子，同列的比例與 Wilson 區間仍公開，例如臺中 4／13,942 仍列 0.0%、0.0–0.1%。［推論］比例加分母近似可反推分子，若要抑制，應連同比例與區間處理，或整列改為「<5」。(c) 分子為 0 的列同樣屬「少於 5」，H 第 34 行「比例機械性接近 0%」的敘述會因此失去依據。

**N4［事實］≥38 的術語在 PLAN 內部仍混用。** PLAN §4 第 58 行「43 席情境下四站休息日剩 5 席以下的比例約 4.0%–7.2%」，≥38 指座位不多（43 席）；PLAN §3 第 48 行與 §6 第 96 行「38 席口徑（已滿）」，≥38 指已滿（38 席）；H 則為「43 席座位不多」。數字都正確，但同一閾值有兩種含義，讀者容易把 38 誤讀為座位數。

**N5［事實］新檔接線與 README 有錯。** (a) `council/novelty-score-conditions.zh-TW.md` 第 3 行的連結 `council/` 指向 `council/council/`，斷鏈。(b) PLAN §10 與 README 皆未指向該檔，評分條件實際上不易找到。(c) README 第 10 行寫 A0「（既有數字，無新算）」，與 H 第 3、7、54 行的日層級重抽不符。(d) README 第 16 行寫「二十七輪」，`council/` 實有第 1–30 輪；README 的評分表只列到第 23 輪。

**N6［事實］H 的驗收段自相矛盾。** H 第 71–73 行仍以「驗收」為標題，卻自陳「結論句未逐句加標籤」「這是目前的限制而非已達成的逐句標示」。建議改名為「限制與自我檢核」。

**N7［事實］H 第 3 行「沒有新算上游資料」與同段後文「以既有到站列做的新重抽」並存。** 建議改為「未新增上游刷卡資料，僅對既有到站列重抽」。

**N8［推論，低優先］G1 警示樣本的累積未在 PLAN 本文說明。** A 第 32 行要求影子期 100 個警示與 100 個實際無空位，發布期另加 100 與 200。PLAN §6 只計無空位事件（瓶頸），警示以 ≥33 約 10–12 週可累積，但本文未寫出。這不改變 104 週結論，但應一句話交代。
