# 估計器合成驗證：初步結果

## 白話摘要

在這個模擬器中，兩種刷卡估計值都遠低於所選的留站延續上車參考值。所有情境的兩次重複，其 95% 區間都沒有涵蓋該參考值。這是負面訊號，但每格只有兩次重複，不能可靠估計覆蓋率；參考值與估計母體也不同，不能把差距當作已證實的因果偏誤。原定每格 100 次，依單次約 0.6 秒估計，完整工作約需 90 分鐘，因此本次縮減，仍需重跑。

## 模擬設計與假設

每次獨立產生 60 日基準和 60 日檢驗資料，四站、兩方向、每日各 28 班；其餘參數沿用 sim.py 預設。a 為被拒乘者留待下一班比例，b 為棄等比例，分別取 0.2、0.5、0.8 與 (1−a) 乘 0.3、0.7。每日跨方向共同需求衝擊的對數常態標準差取 0、0.4、0.8，分別作無、中、強。假設無自願等候；此模擬沒有真實日曆，以日序模 7 代替日類。

基準依站、方向、日類、小時平均上車人數，樣本不足 5 時依序退回不分小時、不分日類。檢驗期按同日同站相鄰可見事件，使用 60 分鐘窗，並要求同站反方向較早最近可見事件亦在窗內。高載為前車上車前載客至少 cap−5，低載低於 cap−10。水平差為主高平均超額減反高平均超額；差中差為主高減主低，再減反高減反低。兩者在共同可配對母體計算。以檢驗期日為單位聯合重抽 500 次，基準固定；每種區間有效重抽不足 90% 則不報。

參考真值是可見高載到站後，下一實際班次同站上車的累積候車人數平均；最後一班排除。程式另輸出共同母體主高組後車平均上車數。兩者母體不同，前者亦可能含更早班次留下的人，故只是可取得的近似參考，並非可精確追溯到指定前車的留站人數。sim.py 沒有個體來源追蹤。偏誤、RMSE 與覆蓋率是相對該參考值計算，每次模擬各自比較其實現的參考值。

## 結果與失敗區域

以下為初步篩選，條件是絕對平均偏誤超過平均參考值 50%，或觀察覆蓋率低於 80%。每格僅兩次，不能據此推論真正的失敗機率或可靠的參數邊界。CSV 保留各情境的數值、有效次數與兩種估計量。小規模及完整矩陣分別獨立執行，種子安排相同的部分可重複，不能視為額外重複。

- cap=42：全部 18 種 a、b、衝擊組合，兩種估計量均符合篩選條件。
- cap=43：全部 18 種 a、b、衝擊組合，兩種估計量均符合篩選條件。

不能單獨歸咎共同衝擊：無衝擊情境也入選，且基準期同樣包含留站、兩方向都會產生延續上車，兩者相減可能消去共同成分。共同需求、班距、不可見零上車事件、負對照本身有留站、以及真值母體不匹配均可能造成差距。此設計無法將它們拆開辨識。

## 限制與後續

本次不含真實資料應用。每格兩次重複遠低於原定 100 次，無法支持穩定的偏誤、RMSE 或覆蓋率結論。應先讓模擬器追蹤每批被拒乘者的來源班次，並在共同配對母體定義對應真值，再以至少每格 100 次獨立重複複驗；每次 bootstrap 固定 500 次。真實資料的歷史基準誤差、日曆、容量不確定與刷卡重建誤差也未模擬。

G0 現場計數可直接觀察前車拒乘、離開及下一班上車，並追蹤其來源，補足刷卡無法識別的留站人數與母體對應；仍須設計代表性抽樣及一致的觀察規則。

重現：以 Python 3 執行 `python3 docs/proposal/drafts/experiments/estimator/validate.py --output 新路徑.csv --caps 37 38 42 43 --repetitions 100 --bootstrap 500`。輸出路徑必填且獨佔建立；估計器 CLI 需指定 `--baseline`、`--visible`、`--output`、`--cap`，讀取兩期可見 JSONL。不要覆寫既有結果。
