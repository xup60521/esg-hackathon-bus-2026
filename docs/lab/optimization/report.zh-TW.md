# 受限制加班與中間站起駛情境求解器

研究與執行日期：2026-11-04。交付範圍為資料、純 TypeScript 求解器、測試與報告。未製作或修改 UI，未提交、推送、部署或開 PR，未讀取或輸出 secrets。

## 摘要

已完成可重現的有限候選精確求解器，保留假設基準班次，在車輛與司機配對、回庫占用時間、可用時段、工作量、加班班數、預算、座位保留與最低服務限制下，選出加班組合。輸出可行證明、有限候選內最優解或不可行，並以獨立驗證器查核可行解。

實際資料選到 2025-03-02 的 6670D 回程，埔里站 14 時上車 125 筆，作為事後壓力測試。假設基準班可保留20席、每班中間站車保留40席、全程加班保留20席，混合候選最優解為3班中間站起駛，加班成本540個假設單位。這是自行設定的情境結果，不能推論當日需加開3班，也不能宣稱已改善營運或節省實際成本。

125筆是已成功搭車的觀測。真實班表與剩餘座位未知，本報告的假設基準供給20席不代表當日實際供給，模型中的105席缺口也不是當日拒載105人。

## 方法與明示假設

### 情境輸入

- 所有125名情境乘客假設14:00已到埔里站，目標為14:59前取得保留席位。此到站假設與刷卡分鐘無關，不估真實候車。
- 1班基準車，保留20席，容量40。基準班不可刪除，成本計為0，代表只計加班增量成本，非基準營運免費。
- 6班候選全程加班，每班保留20席，容量40，加班成本360個比較單位。其餘20席不作服務成效推論。
- 4班候選中間站起駛，每班保留40席，容量40，加班成本180個比較單位。
- 候選服務時刻14:05起每5分鐘一班。這些時刻不是官方發車或到站時刻。
- 全程車在13時以前開始定位，占用270分鐘；中間站車從13:35起占用150分鐘。各班都包含定位、行駛、返庫及恢復，假設回到同一共同車庫，並非實測周轉時間。
- 每組資源是一輛車與一位合格司機的固定配對，可用12:00至18:00，累計占用工作上限300分鐘。工作量包含定位等占用，未包括空檔等待與法律上的完整工時計算。
- 混合情境最多加班6班、預算540、4組資源。其他情境改變指定限制，完整輸入隨JSON保留。

車型40席、保留比例、成本、車庫及時間全部是假設，不取自業者。特別是中間站車保留席位較多、成本較低，本就使其在此模型中占優勢，求解器只是算出假設的結果。

### 限制式與目標

每個候選班次有二元選取變數。基準班固定選取。每個已選班次需指派一組車與司機，並滿足：

1. 同資源班次的完整占用區間不可重疊，可在前班返庫的同一分鐘接下一班。
2. 完整占用區間必須落在資源可用時段內，各資源累計占用分鐘不得超過上限。
3. 加班總成本不得超過預算，加班班數不得超過上限。
4. 每班跨目標保留座位合計不得超過車輛容量，不允許同班同目標重複計席。
5. 保留座位的服務時刻必須在班次占用區間及目標可服務時間內。
6. 每個目標至少達到最低服務班數；完整覆蓋模式另要求保留席位總和達到情境人數。

令目標缺口為 `max(0, 情境人數 − 已選班次保留席位總和)`。依序最小化缺口、加班成本、加班班數。完整覆蓋模式可行解的缺口必須為0；軟覆蓋模式允許輸出缺口，但最低服務仍是硬限制。

求解器枚舉全部候選子集，再回溯指派資源。上限18個候選，最多262,144個子集，資源指派另有組合成本，適合小型情境，不保證大問題的互動延遲。此版本不用新增求解套件。固定輸入與排序下，解與JSON輸出可重現。

保留席位在不同目標間不重用，屬保守配置。沒有OD與逐班資料時，不把不同路段的座位自動重用，亦不宣稱提供全線區間容量最佳化。

`optimal` 只表示已窮舉有限候選、在這份假設下最優，不表示真實營運最優。`infeasible` 只表示這份候選與限制沒有解，不表示現實不可能改善。`rejected` 是依檢查順序歸類的子集淘汰數，並非最小不可行原因集。

混合解選擇基準班與 `midstop-1`、`midstop-2`、`midstop-3`，服務時刻分別為14:00、14:05、14:10、14:15。四個完整占用區間重疊，需4組資源。少一組只能保留20加2乘40等於100席，未達125席；預算539無法買足3班中間站車。這些是可以逐項檢查的限制，不是人次直接除座位數後忽略車輛周轉。

中間站車每班保留席位從40降至30，原限制立即不可行；增加資源與預算才能恢復可行。這個敏感度說明真實剩餘座位資料非常關鍵。全程與混合情境的可用資源、預算也不同，不應從表中直接發布實際節費百分比。

基準枚舉1個子集、全程情境64個，其餘各1024個。4個最優情境均通過獨立可行證明檢查，4個不可行情境均完成全部子集枚舉。

## 限制與後續整合

缺少真實班表，這一版是情境求解原型。要轉為可執行班表，至少需業者提供有生效日期的逐班時刻、站間行車時間與變異、車庫與空駛、車型與可用容量、實際非票證乘客、司機可用班段、休息與換班規則，以及既定班次的資源占用。所有單位成本亦須換成可核對的業者成本。

目前資源是固定車與司機配對，不支援換駕、異地交接、跨線營運、車輛回到不同車庫、電量、充電、無障礙車型或完整勞動法令規則。最低服務只對本情境目標成立，不代表全線各站的服務底線。原有基準班不可刪，但未納入的班次無法受到保護。

未上車需求、排隊順序、到站時間、放棄候車與拒載均無資料，因此不計算實際候車分鐘、拒載人數或完整需求。下車數只用於盤點，不從站時差額推算逐班滿載率。

主代理可直接匯入純函式：

```ts

const errors = solution.status === 'optimal' ? verifySolution(scenario, solution) : null;
```
