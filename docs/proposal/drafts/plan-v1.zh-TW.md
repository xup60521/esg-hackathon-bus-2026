# 6670 不再過站不停：主計畫草稿 v1

## 一、一頁摘要

**對應標準：完整性、技術可行性、創新性、社會影響力**

問題一句話：6670 尖峰時可能在上游客滿，讓中途站乘客不知道能否上車，而現有刷卡紀錄看不到被留下的人。

解法：先由司機記錄滿載過站，結合車上人數訊號；再以站牌、手機和電話提供可信度明確的座位狀態，研究中途站保留座；最後依預約與調度條件評估尖峰加開專車。正班維持現場上車；預約專車另行規劃。任何座位保障或加班都須業者與主管機關確認後才試辦。

關鍵數字：2024–2025 年共 1,800,910 筆已搭乘刷卡旅次、725 個有紀錄日；埔里站與高鐵臺中站雙向占 36.9%。假設 43 席且剩 5 席以下為「座位不多」，休息日桃米坑在有人上車的到站中有 7.2% 屬座位不多或已滿，該比例漏掉滿車過站，且受車輛歸屬與支付涵蓋限制。這些數字不等於拒載率。[站牌回放方法](seats-replay-report.zh-TW.md)

請求：請評審支持以一個中途站及一個尖峰時段進行共同驗證，協助取得業者逐班容量、到離站及過站紀錄，並與主管機關研議可行試辦。此刻請求的是資料與試辦合作，預算仍待報價，並非已取得補助或業者承諾。

## 三、解決方案

**對應標準：完整性、技術可行性、社會影響力**

1. **看見問題。** 司機在安全時機記錄滿載過站及無障礙乘車受阻，附站點、班次、時間與原因；營運端核對。按鍵記的是事件，不是留下的人數。另以刷卡或計數設備推算在車人數，須逐車校準。
2. **中途站上車。** 站牌與手機顯示「有空位／座位不多／已滿／資料不足」，附更新時間與估計限制；資訊不足時不承諾有座。研議中途站保留座、釋放時間及上游影響，配額尚未決定。顯示已滿時提供下一班查詢與預約入口；正班預約規則與既有制度須先確認。
3. **尖峰加車。** 彙整自願預約與可接受時段，評估只收預約的加班專車；提出時間後由乘客確認，未達門檻則通知回到正班或其他選項。可挪移 ±60 分鐘只是模擬情境，不要求所有乘客接受；業者須先核實車、駕駛、保險與許可。不得宣稱已簽待命協議。

配套分階段評估：電話與櫃台代訂、長者與輪椅使用者自願上車預告、轉乘資訊與可能的高鐵銜接保障、異常刷卡人工查核及退款。保障、退款權利、責任和成本均待確認，不承諾自動退款；同站刷卡 6,281 筆、金額合計 NT$122,617 不等於誤扣金額。[發現](../inputs/findings.md)

**使用者旅程。** 中途站乘客查站牌或手機，看到狀態與更新時間；若已滿可查下一班、電話詢問或提出加班意願。系統回覆是否成班及確認期限，未成班提供替代選項。輪椅使用者可選擇告知協助需求，客服確認可停靠站與適用車輛；預告不取代現場協助。

**畫面功能描述。** 站牌顯示班次、方向、三級狀態或資料不足、更新時間與電話；手機另有預約、取消、確認與無障礙資訊。司機端提供停車安全操作的過站事件與更正；營運端列出事件、來源延遲、需求、候選班次及人工核准／取消紀錄。上述為功能需求，並非已有畫面或已接真實系統。

## 四、技術架構與資料流

**對應標準：技術可行性、完整性**

歷史資料經去識別及品質檢查，依同車同日上下車區間回放，產生站點彙總與情境需求；原型僅呈現歷史，不推送即時座位。正式路徑為：票證事件或車上計數、車輛位置及班次／座位表 → 去重、延遲監測與逐班人數校準 → 座位狀態及資料品質判定 → 站牌／手機；司機事件及自願預約另進營運端供人工處置。刷卡不全、延遲、班次對不上、計數矛盾或資料過期時，顯示「資料不足」，由人工確認，不能把缺值當空位。過期秒數、校準頻率及誤差門檻需以實測訂定。

最小蒐集：歷史資料無卡號；公開端只用彙總。預約僅收必要的班次、上下車站、人數、聯絡與必要協助資訊；用途告知、授權、存取權限、加密、刪除期限和事故處置須依適用個資法與業者制度審查，期限目前未定。協助需求不公開，取消後依核定期限刪除；不收診斷資料。見附錄：資料權責、合法基礎、保存期限及資安驗證如何落實？

MVP 是離線歷史篩選、站牌回放與假設情境展示，不連票證、不接受真實預約；正式版才須串接、監控、權限稽核、備援及現場驗收。演算法採透明規則：固定容量與保留規則，先處理下車再計空位；專車在可挪移範圍內尋找可聚集最多預約的時間。不可把同一預約與刷卡人次重複計數。見附錄：可取得哪些介面、延遲及誤差範圍？

## 五、黑客松展示計畫

**對應標準：完整性、技術可行性、社會影響力**

可演示腳本：開啟 repo 的 `/lab?view=seats`，選中途站與休息日，展示歷史到站的三級回放；切換 37／38／42／43 席，說明分類會改變。再開預約專車模擬，選埔里→高鐵週日、20% 預約，對照 ±30 分／25 人門檻與 ±60 分／20 人門檻，分別得到平均每日 0.01 與 1.25 班。兩者同時改變兩項條件，不能單獨歸因於時間彈性；另可固定門檻逐項比較。所有結果標示「模擬、非實際營運」。[原型報告](seats-replay-report.zh-TW.md)

3 分鐘 pitch：第 1 分鐘說明中途站問題、業者公告和資料盲區；第 2 分鐘操作回放與容量敏感度，示範預約情境；第 3 分鐘說明逐步驗證、資料與試辦合作請求，以及尚未知的拒載人數與成本。

還需補做：確認展示機能開啟並準備離線備援；整理固定案例與清楚的假設標籤；以相同班次假設比較現況、上游加班與中途始發，計算候車、未上車次數、上游影響及新增里程。此比較、真正即時串接、司機按鍵和預約功能目前不屬既有 seats 原型。先處理下車再上車，分開受影響人數與重複未上車次數；現場需求未觀察時只作情境。詳見[早期討論](../inputs/A-001-solution-discussion.md)。

## 七、衡量指標與評估設計

**對應標準：完整性、社會影響力、技術可行性**

先選站與時段，記錄介入前基線；試辦期間使用可比的非介入站／日，依星期、假日與班次控制，記錄天候與特殊活動。觀察員計候車人數、未能上車次數及等候時間，司機事件與班次資料交叉核對；同一人錯過兩班記兩次事件，若可匿名追蹤才計一位乘客。按長者、身障者、學生等自願填報分組，樣本不足即不發布可識別小群結果。

| 指標 | 定義／資料來源 | 判讀及決策 |
|---|---|---|
| 未能上車事件率 | 現場觀察因容量未能上車次數 ÷ 觀察到的上車嘗試次數 | 比較前後及對照，另報樣本數與不確定區間；非全線拒載率。 |

## 九、社會影響與 ESG

**對應標準：社會影響力、完整性**

社會面優先量測中途站能否上車及等待時間，並觀察長者、身障者、學生和遊客是否同等取得資訊與協助。現有票種與旅次不能推算受益人數、居民身分或旅次目的；規模要以試辦實測外推並公開條件。

環境面以新增行駛排放減去確有證據的替代運具排放，分列空駛及回程；目前淨效果未知，甚至可能增加排放。治理面由業者負責派車與客服，主管機關審查許可，技術團隊維護資料品質，乘客代表參與驗收；公開彙總指標與申訴管道。複製到其他路線前，重做車型、支付涵蓋、需求與法規評估。見附錄：可受益規模、運具轉移與碳係數如何驗證？

| 本案整合構想 | 將過站事件、可信度分級、非數位管道與預約加班放在同一條中途站改善流程。這是提案組合，並未證明全球首創或已有效。 |
| 尚待查證 | 中途站保留座、外部車輛待命、高鐵保障及自動退款在臺灣的制度、先例與成本；[創新案例清單](../inputs/innovation-cases.md) 尚未逐項獨立驗證，僅作靈感。 |

業者公告索引已有部分預約及特定班次保留座，故不能聲稱首創保留座。見附錄：臺灣及國外同類服務的現行功能、適用對象、成效與來源各是什麼？

## 十二、待向業者／公路局確認

**對應標準：完整性、技術可行性、社會影響力**

1. 業者：車機代碼與實體車、班次如何對應？各車核定座位及輪椅設備為何？跨日、換車如何記錄？
2. 業者／票證方：上下車、現金、預約票、孩童及漏刷如何計入？上傳延遲、授權、費用與資料品質為何？
3. 業者：現行保留座及預約規則、滿車過站、客訴、退款與無障礙協助紀錄能否提供？
4. 業者：可用司機、車輛、工時、保險、加班成本與停靠點限制為何？外部遊覽車可否合法支援？
5. 公路局：加班、預約專車、跨業者合作、停靠、票價與補助需要何種許可？責任歸屬與稽核要求為何？
6. 雙方及乘客代表：保留配額、釋放時間、電話服務、無障礙安排、隱私保存期及停止試辦的門檻如何訂定？
7. 高鐵與相關方：銜接資訊與保障的責任、條件、上限與費用可否協商？

## 十三、決策點與替代方案

**對應標準：完整性、技術可行性、社會影響力**

| 決策點／否定證據 | 行動與替代方案 |
|---|---|
| 無逐車容量或即時資料；或現場誤報過高 | 不公開座位推估，改人工過站紀錄、歷史趨勢及電話資訊；達成校準門檻後再評估。 |
| 現場顯示中途站需求小或主要問題不是滿車 | 停止以拒載為主訴求，改處理實測最大問題；保留觀察結果與分母。 |
| 保留座造成上游嚴重排擠或空座 | 降低、釋放或取消配額，改比較中途始發加班；重新量測上下游影響。 |
| 預約不足、乘客無法挪時或爽約過高 | 不強行成班，改固定時刻加班或改善正班資訊；以報價與現場數據重算。 |
| 法規、駕駛或預算不允許加車 | 暫停專車，先做過站紀錄、人工查詢及無障礙協助，不承諾新增運能。 |
| 評估顯示淨排放增加或受益分配不公平 | 調整班次或停止擴大；公開新增里程、各群結果及不確定性。 |

見附錄：各項決策的可操作門檻、替代方案成本與核准責任，待業者、主管機關和乘客代表共同確認。
