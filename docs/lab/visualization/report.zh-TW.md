## 方法

### 資料轉換（`scripts/lab/visualization/build.ts`）

把 `midstop.json` 轉成欄式 `cube.json`：每筆以整數 `((支線×3+方向)×站數+站)×24+小時` 編碼，另存上車、下車與依日期排序的偏移量。同一套彙總程式（`src/features/lab/visualization/model.ts`）在頁面、建置腳本與測試中共用，避免頁面與報告數字不同。

### 篩選與彙總（`analyze`）

篩選條件：支線（多選）、方向（全部／去程／回程）、站點（多選）、日期區間、日類型。

- **有紀錄日（active）**：資料集當天有紀錄，且所選支線之一當天有紀錄。**日均與各小時平均的分母只計有紀錄日**；只在有紀錄日把沒有人的小時視為 0。零值不代表當時有班次。
- **缺資料日（missing）**：整個資料集當天沒有任何紀錄，不補 0、不進分母。
- **所選支線無紀錄（inactive）**：資料集當天有紀錄但所選支線沒有，另計數、不進分母。
- **日類型排除（excluded）**：先依日類型篩選；被排除日類型的缺資料日不會被報成缺資料。
- 方向篩選為去程或回程時，「無法判定方向」的人次被排除，並在頁面上顯示被排除的量。
- 站點篩選只改變上方統計；各站圖永遠顯示全部 16 站（套用其他篩選），避免選一站就看不到別站。選取的上車與下車是「這幾站的刷卡次數」，不是這些站之間的旅次。

### 指標定義

| 指標 | 公式 | 不計算的情況 |
|---|---|---|
| 日均 | 合計 ÷ 有紀錄日數 | 有紀錄日為 0 時顯示「–」 |
| 最高峰小時與占比 | 全時段加總中最大的小時 ÷ 合計 | 合計為 0 時 null |
| 前三高小時占比 | 三個最大小時合計 ÷ 合計 | 同上 |
| 休息日 ÷ 上班日 | 休息日日均 ÷ 上班日日均 | 任一類少於 5 個有紀錄日，或只有單一日類型時 null |
| 7 日平均 | 前後各 3 天窗口內**有紀錄日**的平均 | 窗口內有紀錄日少於 4 天則斷線 |
| 星期×小時 | 該星期該小時合計 ÷ 該星期有紀錄日數 | 該星期無有紀錄日時顯示斜線；少於 5 天於提示註明 |

### 日類型

使用行政院人事行政總處《政府行政機關辦公日曆表》的「是否放假」欄位：2（放假）為休息日（含週休、國定假日、補假），0（上班）為上班日（含補行上班日）。2024 年用 113 年版；2025 年用 114 年版（1141020 更新），該檔為 Big5 編碼，腳本會轉碼。這是政府機關日曆，只**近似**旅遊需求日：補班日、連假中間的橋接日（例如多人請假的平日）仍歸上班日。

### 視覺與互動

沿用主代理的 `/lab` 共用外殼與元件（`src/components/lab/shared`：Section、Field、Segmented、Stat、KindBadge、FreshnessBanner、SourceList、Provenance、LimitationList）以及既有首頁／分析頁的色票與 CSS 變數（上車藍、下車橘、休息日綠），未新增色票。圖表為手寫 SVG，沒有新增依賴。圖上有 hover 提示；點每日長條可只看那一天；休息日用顏色加圖例區分，缺資料日用斜線而非顏色。UI 由 Claude 實作，未使用 GPT 或 Gemini 做視覺決定。

## 限制

1. 刷卡只記錄**成功上車**者：沒有候車、未上車、客滿、拒載、容量與班次資料。人次不能解讀為完整需求、擁擠或載客率；尖峰人次可能被車輛容量限制。
2. 人次不是旅次數：一趟旅次的上、下車分屬兩個站；篩選少數站後的數字是這些站的刷卡次數。
3. 方向由 OD 站序推定，同站與未知起訖（6,281 人次）無法判定；沒有班次 ID，不能談同一班車的關係。
4. 6 個缺資料日的原因未知；「沒有紀錄」不等於零需求或停駛。E 支線只有 427 天有紀錄。
5. 日類型為政府機關辦公日曆，只近似旅遊需求日；沒有天氣、活動、學校行事曆與票價優惠資料，所以月份差異與單日高低不能歸因。
6. 資料為歷史（至 2025-12-31），非即時。
7. 星期×小時在「休息日」篩選下，平日欄位只含少數國定假日／補假，天數少（提示會標示），僅供參考。
8. 休息日與上班日的比較是描述性統計，未做顯著性檢定或控制其他因素。
9. 本頁沒有 URL 狀態保存（重新整理會回到預設篩選）；圖表為手寫 SVG，鍵盤只能操作篩選按鈕與日期輸入，圖上 hover 提示與「點長條只看一天」沒有鍵盤版本（鍵盤使用者可用日期輸入選單日，月別表可作文字替代）。
