# 上游載客定義比較 v4

沿用 run.py 的事件篩選、同車同日上車到站及相鄰到站配對；A 是上游最後一次上車後的載客。B 從該次上車之後按時間及同秒先下後上順序掃描，僅扣除上游同站的下車；遇到其他站的任何事件，或距最後上車超過 600 秒即停止。這是可重現的保守停靠代理，不是 GPS 離站實測。相同時間的其他站事件依資料原始順序處理；其他站下車一律不扣入 B。該規則不同於審查員未完整指定停靠界線的估法，因此數值不必相同。

相同樣本與標籤：目標站上車前載客 ≥ cap−5。訓練至 2025-03、選擇期 2025-04 至 06、留出期 07 至 12。H 為同星期／三小時歷史均值，R 為上游載客 ≥ cap−5，M 為以歷史均值與對應 A 或 B 載客重訓的邏輯斯模型。H、M 門檻依選擇期 10% 預算選擇，平手不拆；R 不保證相同警示比例。基率＝正例／樣本；lift＝精確率／基率。無警示時精確率與 lift 未定義。

全樣本 20,079 筆，A 與 B 分別均無目標站上車前載客高於上游載客的情形，B 相對 A 改變 126 筆。因相鄰上車間無其他上車，R 的 cap−5 召回率為構造結果，不能解讀為預報能力。B 的扣減只限上游同站事件，遇到其他站立即結束，不使用其他站的下車人數。到站與同車同日不代表真實班次，資料也沒有零上車過站；即時能否取得該站最後事件亦尚未驗證。
