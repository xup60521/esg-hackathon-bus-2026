# 滿車溢出訊號：實驗尚未完成

目前沒有可供簡報的效應量，也沒有可辯護的留站人數下限。已建立分析程式並啟動計算，但全情境的日重抽與置換運算未能在本次完成；中斷前沒有產生結果，不能據此宣稱有或沒有溢出。

| 簡報項目 | 現況 |
|---|---|
| 前車接近滿載後，下一班是否多載客 | 尚未取得結果 |
| 可歸因於溢出的年人次 | 未知，不能估算 |
| 下一步 | 修正與加速分層重抽，完成負對照及敏感度，再評估是否存在可檢驗訊號 |

程式位於 `experiments/spillover/run.py`，以唯讀方式開啟資料庫，輸出檔必須是新路徑。它沿用 v4 的旅次篩選與車日載客重建，按同車連續上車是否換站或間隔超過 10 分鐘建立事件，以站序推得各刷卡旅次方向並投票；平手及無方向事件排除。只配對同站同方向相鄰有紀錄到站、同日不同車，無人上車的中間班次不可見。其負對照使用同日、相反方向、不同站的近期載客，仍可能受到共同需求衝擊。

目前程式仍有方法缺口：低、中載客尚未分開報告；所謂基準使用同一分析期的分層非高載組，並非獨立歷史基準；日重抽和置換各僅設 100 次，尾端區間精度不足；程式年化暴露只涵蓋可配對且具分層對照的事件，並非全部高載到站。必須先處理這些缺口及運算效率，才能解讀結果。對照也需核查資料完整性和方向配對，並考慮班距及同日共同需求的混雜。

即使未來算出正的超額上車數，也不能直接證明是留站人數：尖峰和班距等混雜可能高估，棄等、改搭與放棄行程可能低估。乘以年化高載事件數只能是其他混雜為零等假設下的觀測換算，並非統計或因果保證的下限。結果不顯著也不等於沒有溢出。

對 PLAN 的建議目前維持原文「刷卡看不到未上車者，需現場量測」；可另加一句：「團隊正測試前車高載與下一班上車量是否相關，結果尚未取得，不能推算受益人數。」
